# BGA 農家樂記牌器

繁體中文 ｜ [简体中文](README.zh-CN.md)

Board Game Arena（BGA）農家樂（Agricola）的 Chrome 擴充功能。幫你記住輪抽（draft）時看過、傳出去的牌，推論這些牌現在在誰手上，並直接顯示在每位對手的農場下方。主要針對**競技場**（4 人，9 張選 7，職業卡和次要發展卡一起輪抽）。

> 目前是試用版。輪抽推論用真實的 4 人競技場對局重播和實戰對局驗證過，遇到問題歡迎回報。

## 農場上的推測牌

推論出來的牌會用 BGA 原本的卡牌樣式，放在每位對手「已打出」的牌下方、虛線隔開的「推測的牌」區塊裡，並且一律調暗（只有真正打出的牌是正常亮度）。右上角的圖示表示狀態：

| 圖示 | 意思 |
|---|---|
| ★（紅，實線框） | 確定在他手上：你傳出的牌堆傳回來時少了這張，而且只可能是他拿的 |
| ?（灰，虛線框） | 可能在他手上：會同時出現在每位候選玩家底下。滑鼠移上去會放大卡牌，並顯示完整候選，以及是否也可能已被棄掉 |
| ✎（紫，實線框） | 你的猜測，見下方「猜牌」 |

卡牌左上角的標籤都是**以你的角度**寫的。「我第5輪傳出 4選1」表示：這張牌在你第 5 次選牌時的那疊裡，你沒拿、傳了出去；如果它在這位玩家手上，他是從這 4 張同類型的牌裡選了 1 張（所以這 4 張裡最多只有 1 張在他手上）。

點推測牌（或卡上的放大鏡）會像真正的卡一樣放大顯示。

為了不擠爆版面，農場上只放候選 **2 人以內**的牌。「三個對手都有可能」的牌縮小後集中放在中央行動板下方的「三個對手都可能」區塊，依你傳出的輪次排列，左上角的「我第N輪傳出」表示它在你第 N 次選牌時的那疊裡，滑鼠移上去可以看完整卡牌和候選。對手出牌後，排除推論會縮小範圍，牌會自動從這個區塊移到對應對手的農場上。點浮動面板的 🃏 可以開關這些顯示。

## 猜牌

滑鼠移到 ? 推測牌上，會出現「✎ 猜是他的」按鈕：

- 在對手農場上的牌：點一下就猜是這位對手拿的。
- 在「三個對手都可能」區塊的牌：點 ✎ 會跳出候選人讓你選。
- 猜過的牌會移到被猜的對手農場上，紫色實線框、右上角 ✎；再點「取消猜測」就恢復。

程式會把你的猜測當成已知條件繼續推論：被猜的人會從同一疊牌其他同類型牌的候選中排除，其他牌的範圍可能因此縮小。**只因為你的猜測才推出來的結果會用紫色虛線標示**，提示裡寫「（依你的猜測）」；紅色 ★ 確定只來自真實資訊，不受猜測影響。

如果之後有人打出的牌和你的猜測矛盾（例如你猜在 A 手上，結果 B 打出來了），猜測會自動取消，頁面上方會出現提示。猜測依牌桌存檔，重新整理頁面也不會消失。

## 已打出的牌：第幾輪選的

對手真正打出的卡，左上角也會標出他是第幾輪選的：

| 標籤 | 意思 |
|---|---|
| **首選**（金色） | 他第 1 輪從自己那疊全新的牌裡選的。你的下家（你傳牌給他的人）打出你沒看過的牌，一定是首選 |
| **我第N輪傳出**（藍色） | 你第 N 次選牌時看過、沒拿、傳出去的牌 |
| **我沒看過**（藍色） | 你在輪抽中從沒看過這張牌（不是下家的首選） |

只有從第 1 輪開始完整記錄輪抽時，才會標「沒看過的牌」；輪抽中途才裝的話，這部分會停用。

你自己打出的牌和手上的牌會標「我第N輪選」（第 1 輪標「首選」）。

## 浮動面板

左上角的「🌾 記牌器」，預設收合，點 ▾ 展開。裡面列出全部推測：每位玩家一區，✓ 已打出、★ 確定、? 可能（包括三人候選的牌）、✎ 你的猜測，最下面是「已被棄」和「我的牌」。

推論依據：

- **傳牌方向**：會自動判斷。
- **候選範圍**：根據剩下的輪數，算出這張牌還可能被哪幾位玩家拿到。
- **排除推論**：每人每輪每種牌只拿 1 張。所以有人打出同一疊牌裡的另一張同類型卡後，他就會被排除。

面板標題列的按鈕：简/繁 切換簡體或繁體、🃏 開關農場上的推測牌、↻ 重新讀取牌桌、⤓ 匯出紀錄（JSON）、✕ 清除本桌紀錄、▾ 展開 / 收合。面板可以拖曳。

紀錄依牌桌分別存在你自己的瀏覽器裡，重新整理頁面不會遺失。

## 安裝方法

需要使用 **Chrome** 或 **Edge** 瀏覽器（電腦版）。

1. 下載：點這個頁面上方綠色的 **Code** 按鈕，選 **Download ZIP**，然後解壓縮到一個固定的資料夾。之後別刪掉或搬走這個資料夾，擴充功能會直接從這裡讀取檔案。
2. 打開擴充功能管理頁：Chrome 在網址列輸入 `chrome://extensions`，Edge 輸入 `edge://extensions`。
3. 開啟右上角（Edge 在左下角）的 **開發人員模式**。
4. 點 **載入未封裝項目**，選擇剛才解壓縮出來、裡面有 `manifest.json` 的那個資料夾。
5. 進入 BGA 的農家樂牌桌（已經開著的話請重新整理頁面），左上方就會出現「🌾 記牌器」面板。

**更新方法**：下載新版 ZIP，覆蓋原來的資料夾，再到擴充功能管理頁點這個擴充功能的重新整理按鈕。

## 在 Android 手機上使用（Firefox）

Android 版的 Chrome 不支援擴充功能，所以手機上要改用 **Firefox for Android**（128 版以上）。Firefox 正式版只接受經過 Mozilla 簽署的擴充功能，所以要先簽署一次：

1. **打包**：在專案資料夾執行 `./scripts/build-firefox.sh`，會產生 `dist/bga-agricola-card-recorder-firefox.zip`。
2. **（建議）先在電腦版 Firefox 試用**：網址列輸入 `about:debugging#/runtime/this-firefox`，點「載入暫用附加元件」，選 `dist/firefox/manifest.json`。關掉 Firefox 後就會移除。
3. **簽署**：用 Mozilla 帳號登入 [addons.mozilla.org 開發者中心](https://addons.mozilla.org/developers/)，選「提交新附加元件」→「自行發布」（不上架到商店），上傳上面的 ZIP。通過自動審查後，下載簽署過的 `.xpi` 檔。
4. **在手機上安裝**：把 `.xpi` 傳到手機。Firefox →「設定」→「關於 Firefox」，連點 Firefox 標誌 5 次打開除錯選單，回到「設定」就會出現「從檔案安裝附加元件」，選擇 `.xpi`。
5. 如果裝好後在 BGA 上沒有反應，到 Firefox 的附加元件管理 → 這個附加元件 →「權限」，允許存取 boardgamearena.com。

簽署過的 `.xpi` 也可以直接分享給朋友安裝。

> 手機版的 BGA 版面比較窄，推測牌和面板是照電腦版設計的，可能會比較擠。

## 注意事項

- **一定要在輪抽開始前裝好**。BGA 不會重送輪抽紀錄，裝好之前的輪抽無法補記。
- 觀戰時看不到輪抽和手牌，初學者模式沒有職業卡和次要發展卡，這兩種情況面板都沒什麼內容。
- 面板會依瀏覽器語言自動顯示繁體或簡體；也可以點標題列的「简/繁」切換，選擇會被記住。卡牌名稱則依你 BGA 的語言設定。
- 這個擴充功能只讀取你自己瀏覽器裡的遊戲畫面資料，不會上傳任何東西，也不會替你操作遊戲。

## 技術細節

### 運作方式

| 檔案 | 執行環境 | 職責 |
|---|---|---|
| `src/inject.js` | 頁面 MAIN world，所有 frame | 等 `window.gameui` 載入，讀取 `gamedatas` 送出快照，並包一層 `gameui.notifqueue.dispatchNotification` 來轉送追蹤的通知 |
| `src/content.js` | isolated world，所有 frame | 處理記牌狀態、存檔，以及用 shadow DOM 畫面板 |
| `src/background.js` | service worker | 開發用：以「載入未封裝項目」安裝時，偵測檔案變動後自動重新載入 extension，並重整 BGA 牌桌分頁 |

正在進行的牌桌（`/tableview?table=N`）裡，遊戲跑在 `iframe#gameIframe`，所以兩支腳本都設了 `all_frames`。

Firefox 版和 Chrome 版共用同一份程式碼，只有 manifest 不同（`manifest.firefox.json`，需要 Firefox 128 以上才支援 `world: "MAIN"`），也不包含開發用的 `src/background.js`。`scripts/build-firefox.sh` 會把它組到 `dist/firefox/` 並打包成 ZIP。content.js 透過 `globalThis.browser || globalThis.chrome` 取得擴充功能 API。

用到的通知：`newDraftPile`、`add/remove/confirmDraftSelection`、`draftWaiting`、`draftProgress`、`clearDraftPools`、`draftIsOver`、`refreshHand`、`buyCard`、`buyAndPassCard`、`buyAndDestroyCard`。打出卡的人以 `args.player_id` 為準，因為 `buyAndPassCard` 的 `card.pId` 是傳出後的狀態。

### 輪抽推論

- 傳牌方向：從 `draftWaiting.predecessorId`（傳牌給我的人）判斷。在實際的 4 人局裡，整場輪抽方向固定，都是傳給 `playerorder` 的下一位。
- 候選範圍：我在第 t 輪傳出的牌，只可能被下家 1…k 拿走，其中 k = min(玩家數 − 1, 總輪數 − t)。如果這疊牌傳回來時少了某張，就一定被拿走了；沒傳回來的則也可能被棄。
- 排除推論：每輪每人每種牌只拿 1 張。如果某位玩家打出了同一疊牌裡另一張同類型的牌，他就被排除。

### 驗證

- 用一場真實 4 人局的重播（重播裡包含所有玩家的私人輪抽頻道）做回放：只把我自己頻道收到的通知餵給 content.js，再拿全部玩家的選牌紀錄當正確答案比對，所有判斷都正確。
- 同一場重播也確認：新的一疊牌一定在我確認選牌之後才送達。

### 測試與交接

- `npm test`：用真實 4 人競技場重播資料做回放測試，加上隨機模擬（`tests/`）。
- 接手開發請先讀 [docs/HANDOFF.md](docs/HANDOFF.md)。

### 除錯

- 遊戲 iframe 的 DevTools console 裡，`window.__agrRecLog` 保留了所有追蹤到的原始通知。
- `livingHand*` 這類輪抽方式目前只會記下卡牌名稱，不會納入記牌邏輯。
